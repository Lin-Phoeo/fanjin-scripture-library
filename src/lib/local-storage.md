# 本机书斋数据契约

静态入口调用 `dispatchLocalApi(path, init)`，返回原页面所需的数据对象。适配层只读取站点静态 `content/index.json`、`content/books/{slug}.json`、`content/search.json`；不会向服务器提交个人数据。

个人资料保存在 IndexedDB 数据库 `fanjin-local-v1`，对象仓库 `app` 的 `state` 记录中。默认只有一个本机书斋（用户编号 1），没有密码、会话或远程管理员。收藏、段落书签、摘录快照、精确进度、阅读兴趣、自修计划及每日记录都进入该记录。浏览器外观设置由现有阅读偏好模块保存，未混入本机备份。

`changeLocalState` 在同一个 readwrite 事务中读取、验证、修改和写回；不同标签及并发操作由 IndexedDB 串行化。回调必须同步，不可在事务内等待网络。AbortSignal 在提交之前会中止事务；提交已经完成后不会假称未保存。保存失败不会退回临时内存模式。

导入和清空还会递增对象仓库中独立的 `replacement-epoch`。写操作在读取静态书籍前记录该版本，提交事务时再次核对，因此恢复前启动的迟到写入不能覆盖恢复结果。替换开始/结束经 `BroadcastChannel('fanjin-local-data')` 和固定 `fanjin-local-data-signal` 存储标记通知其他标签，接收页派发 `fanjin-local-data-changing` / `fanjin-local-data-updated` 事件；界面须取消尚未调用 API 的延迟保存及临时编辑状态，再重新读取记录。广播不携带笔记正文或备份内容。

备份结构为 `{ format: 'fanjin-local-backup', version: 1, exportedAt, data }`。仅解析白名单应用字段，不写入任意 localStorage 键。导入前验证完整结构、稳定标识、编号、日期、计数和计划引用，验证通过后才用单事务替换。替换不依赖旧记录可解析，因此可用有效备份修复旧记录损坏。已从公开目录撤下的经典仍保留私人摘录、书签和计划快照。

上限按 UTF-8 字节计：本机应用数据 19,000,000 字节，导入 JSON 20,000,000 字节。每类集合最多 100,000 行，心得最多 10,000 字符，原文快照最多 100,000 字符。超限及磁盘配额不足都会报错且不覆盖原记录。

定课采用设备本地日历，允许当天及此前三个日历日；同一计划同一日期只保留第一条记录，重复请求不会叠加时长。备份导入可恢复更早的历史记录。所有作品与段落使用发布目录中的稳定 slug 关联，笔记修改只改心得，不改摘录原文。

本机数据清除只替换本应用的 IndexedDB 状态。界面另负责清理已列明的外观、临时草稿等本应用键，禁止调用 `localStorage.clear()` 清除同源其他内容。
