# 跨模型协作试点任务书

此为首轮试点草案。吸收Gemini报告并核验后的最新步骤见 [修订交接单](../gemini-report-review/CODEX_PILOT_HANDOFF.revised.md)；本文件保留原始任务拆分供比较。

状态：准备完成，尚未安装编排器或发起真实模型任务。日期：2026-11-21。

## 目标与候选

验证“多个模型渠道协作能否缩短实际交付时间”，保留用户已有CLI、项目规范和代理7890设置。首个候选为HMB；若希望直接采用多项目工作台，用AO作为替代测试对象；T3用于对照同CLI多渠道实例。一次只运行一套编排器，不叠加任务生命周期。

## 角色与资源

| 角色 | 职责 | 写入边界 |
| --- | --- | --- |
| Host | 澄清目标、拆任务、冻结共用接口、验收、集成 | 集成checkout，公共契约与锁文件独占 |
| Worker A | 梵烬大经数据加载与检索方向 | 先只读；实施时独立worktree，只改指定数据模块 |
| Worker B | 阅读界面、加载状态与兼容行为 | 先只读；实施时独立worktree，只改指定UI模块 |
| Reviewer | 核对不变量、差异、测试证据，要求返工 | 只读实际差异；不能自己宣布发布成功 |

不要把角色固定到某个品牌的能力传闻。选择你已拥有、实际可用的两个或三个渠道，先保证指令遵循和工具能力，再比较速度/成本。

## 第一步：配置与身份

1. 记录实际可执行路径与版本，避免本机DSH两个安装入口混用；新工具放在独立位置，保留原配置备份。
2. 记录每个Worker的harness/provider/model/effort和凭据来源类型，密钥不写入此文件。
3. 检查7890体检结果、实际进程环境和服务端协议；各进程配置不依赖不停切换全局当前provider。
4. 通过原生目录/配置读回确认模型身份；“请求值”和“实际读回值”分列。未知身份不能通过。
5. 明确最大同时工作者数、模型用量上限和本次最长执行时间；自动Router初次关闭，人工明确指定Worker。

完成条件：每个指定Worker可被编排器发现，配置不交叉污染，停止后不遗留未归属进程。仅目录探测成功不算模型请求成功。

## 第二步：只读协作任务

Worker A任务：

> 阅读项目AGENTS及相关架构章节。只检查scripts/build-catalog.mjs与src/lib/local-catalog.ts，评估把最大经典从按书加载改成按章加载的最小数据契约。保持已发布书目/段落slug、原文和私人摘录快照。输出建议字段、旧链接兼容方式、失败恢复与测试条件；引用实际代码位置。只读，不安装依赖、不运行导入、不修改配置或原文。

Worker B任务：

> 阅读AGENTS和DESIGN。只检查BookPage、ReaderPage与tests/e2e中的相关流程，提出按章加载后的加载提示、目录定位、书签恢复、简繁切换、320px及网络失败验收条件。保持当前已认可的视觉设计，输出实际代码依据及需与数据契约协调的事项。只读，不开用户浏览器、不清理私人数据。

Host收集两份结果后先解决契约差异，再交Reviewer核对。不要把两份建议简单拼接；必须指出冲突如何裁决。

完成条件：从派发到回报自动可追踪，Owner能发补充说明，结果有实际代码依据，Reviewer能指出未覆盖条件。没有实际请求时本步骤状态保持未执行。

## 第三步：有界实现与集成

在前述契约确认后，分配互不重叠的文件所有权与独立worktree。Worker只提交任务范围内变更和验证证据。Host审阅差异、整合后运行项目现有 `npm run check:release`；自动创建工作树不代表自动批准合并或发布。

与当前任务无关的书目扩刊、服务器恢复、账号同步、全站重设计不纳入试点。

## 第四步：故障与清理

- 在测试仓库取消一项进行中的工作，检查原生进程是否真的停止，不能只看任务卡变成cancelled。
- 让一项验证故意失败，检查是否退回原任务、保留结果，避免重复提交和无限重试。
- 关闭再恢复控制面，检查运行中任务及结果是否可接续；在测试范围内确认服务归属，不关闭用户正常终端。
- 检查自建浏览器/context/临时preview是否释放，用户原有标签保留；未确认停止的资源不得盲目删除。
