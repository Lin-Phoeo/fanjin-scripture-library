# 最终组合建议的独立反向审阅

日期：2026-11-21。范围：既有六套组合、原始试点、Gemini复核与修订交接单的桌面交付审阅。只读已有材料；没有安装编排器、读取凭据、创建工作树或调用模型。

## 最需要在正式报告中修正的五点

1. **把“长期主选”改成“最贴近目标的首个候选”，保留明确路线。** T3有实例配置和统一会话的文档证据，但尚无本机真实渠道、Windows取消恢复和双工作树交付证据。可以明确建议先试T3，不能把它写成已经证实稳定的最终答案。主推荐写法：“愿意换统一入口，先试T3；坚持当前Codex/Claude入口，先试HMB；主要买API且不在意原生CLI品牌，比较OpenCode/DSH单运行时基线。”无需用户按六套逐个试完。
2. **逐套填清“能选哪个渠道”，不要把provider名当端点切换证据。** HMB现有DSH包核对证明的是ACP声明的`[provider,model]`选路，不支持外推所有harness。Codex/Claude是否仅发现当前原生渠道，须引用本轮专门复核；不要仍写成任意多站点实例都可派发。可行的最小组合是Codex当前渠道A、Claude当前渠道B，加DSH明确声明的渠道C。T3也分别列Codex独立home、Claude实例环境/配置目录、OpenCode原生provider来源；不能一概承诺统一注入策略。
3. **消除两份试点的候选冲突。** `PILOT.md`仍以HMB为首候选，`RECOMMENDED_STACKS.md`以T3为长期主选。桌面只提供一份权威试点，把旧稿明确标为被替代；不要复制两份让新代理自行裁决。研究文件里的相对链接移到桌面后需要重写或复制相应文件。
4. **工作树只有一个生命周期所有者。** “负责人预建worktree”与“T3/HMB自动创建”必须择一。负责人定义base、文件所有权与验收，所选编排器或负责人中的唯一一方创建/取消/回收。共享类型、锁文件、索引/生成清单指定单一写入者。多worktree也仍共享Git对象/refs；它不是独立仓库或操作系统沙箱。
5. **不能用厂商品牌代替可用性或审阅独立性。** GPT做数据、Claude做UI只是起始分工；实际按所选渠道的工具调用、流式、上下文、配额和现有任务表现确认。不同URL不证明不同物理上游；不同模型但同一长对话和同一假设也可能共同漏错。审阅者须独立会话、固定差异与验收条件，并用测试补盲。

## 最小“完整组合”应具备的字段

每套报告至少给出同一张映射：用户入口、负责人运行位置、两名Worker的原生runtime、渠道配置来源、派发API、结果回传方式、工作树所有者、集成者、最终门禁、失败停点。没有已核接口的地方直接写待实联，不给伪配置代码。

T3方案尤其写明：内部主代理才调用caller-only delegate；外部Codex用thread launch/read/wait。写任务显式worktree，因为默认shared。不要让用户误以为安装MCP后现有桌面助手即可拥有内部delegate身份。HMB不是无需宿主理解的自动总包，Host仍须派发、追踪、检查与接受结果。

OpenCode 1.x/2.x迁移需要在本轮兼容性核对后加入明确限制；若共享数据库迁移不允许并存，不能将“更新一下OpenCode”作为无影响准备动作。AO/Worktree Kanban的“审阅/返工列”不等于独立只读审阅或项目门禁已经通过。

## 验收和成本的可执行标准

- 状态分开列：文档核对、发布包/源码核对、纯函数离线检查、原生只读往返、并发实现、取消恢复、正式发布。当前前三者有证据，后四者不能填通过。
- 实施成果固定到commit/tree；检查已提交、暂存、未暂存、未跟踪项。最终在同一集成工作树运行`npm run check:release`，记录构建与浏览器回归属于同一成果；不复用旧dist“绿色截图”。
- 测量从任务收到到可交付的总时间，含设置、派发、等待、协调、整合、测试、返工；另记录人工复制/干预次数、有效成果、失败尝试和真实用量。字段缺失保留unknown，不当0；不要先许诺倍数或固定省钱率。
- 用同范围验收比较单代理与双Worker；先两个Worker、每渠道并发1、一次有界返工。预算/超时是待定运行参数，不把建议数字写成用户已批准的支出。
- 错误到达上限后停在明确阶段；自动fallback须防止重复任务和原生CLI内部重试叠加。输出静默、进程退出、UI完成、模型终态和被接受是不同事实。
