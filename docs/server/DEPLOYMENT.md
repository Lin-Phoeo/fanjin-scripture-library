# 部署与恢复

梵烬是公益个人自修驿站，以佛、道经典为主，兼收诸子百家。多人共修、活动报名与讨论接口已退役，返回 HTTP 410。生产服务由 Express 同源提供前端与 API，SQLite 存放账户、私密阅读记录及内容。

## 交付前验证

使用 Node.js 22.14 或以上（建议 Node.js 22/24 LTS）：

```sh
npm ci
npm run check
npm audit --audit-level=moderate
```

`check` 包含 ESLint、前端/后端/构建配置严格类型检查、Vite 生产构建和隔离测试。`npm test` 自动启动随机端口的后端和临时 SQLite，结束后停止子进程并删除临时目录，不接受外部 API 地址，也不写入正式数据库。覆盖权限、私人笔记、阅读进度、简繁检索、内容发布与快照、个人功课、账号恢复、迁移在线备份与回滚。

## 生产配置

将 `.env.example` 复制为 `.env`，设置独立管理员及随机密码（至少 12 字符），使用 HTTPS 域名。配置文件和备份仅给予运维账户读权限。

| 变量 | 用途 |
| --- | --- |
| `FANJIN_DB_PATH` | 持久数据库绝对路径 |
| `FANJIN_BACKUP_DIR` | 迁移及人工备份目录 |
| `ADMIN_NAME` / `ADMIN_PASSWORD` | 首次生产初始化管理员，已有管理员不会被重置 |
| `HOST` / `PORT` | 监听地址与端口，直接运行时默认 127.0.0.1:3001 |
| `CORS_ORIGINS` | 允许写请求的完整来源，多个用逗号分隔 |
| `TRUST_PROXY` | 仅在所有入口都经过一个可信反向代理时设为 1 |
| `SEED_DEMO` | 生产必须为 0；示例账号/数据仅供隔离开发测试 |
| `AUTH_REGISTER_LIMIT` | 每个可信网络对端每小时注册请求上限，默认 10；东京覆盖为 60 |

`npm start` 强制生产模式并加载 `.env`，没有 `dist` 时拒绝启动。生产不生成示例账号；已有库含使用公开示例密码的活跃账户时拒绝启动，需先修改或停用这些账户。登录 Cookie 在生产强制 Secure，请勿通过公网明文 HTTP 使用账号功能。

## Docker

小内存服务器使用本地验证后的 `dist/`，运行镜像只安装生产依赖。

```sh
npm run check
docker compose build
docker compose up -d
docker compose ps
curl --fail http://127.0.0.1:3007/api/health
```

服务仅映射本机 3007，使用独立 `fanjin-data` 持久卷。数据库与备份在 `/data`；容器以非 root 身份运行。更新代码前运行在线备份，再构建、重建容器；不要执行 `docker compose down -v`。不与其他项目共享数据库、Compose 项目名或容器网络。

东京 Azure 现有多个业务共用入口。正式域名为 `fanjin.curatix.tech`，应将现有 HTTPS 路由新增到梵烬独立服务；修改前保留入口配置，验证配置语法及其他域名，不能替换既有业务配置。若独立 Caddy 经 443 SNI 透传接入，应只给新域名新增路由，确认 TLS-ALPN 验证链路和证书后再验收。仓库 Compose 不自动修改主机 Nginx、DNS、证书或其他服务。

当前东京入口的 Nginx SNI 透传没有 PROXY protocol，Caddy 收到的网络对端并非原始访客 IP。应用不能据此宣称拥有每访客 IP 限流：登录/账号恢复按规范化账号名哈希与可信对端组合限流；改密码/重置恢复码按已认证用户 ID 限流；一般 API 仍保留总量限制。注册额度是共享网络对端的额度，东京覆盖为每小时 60，未取消防护。若以后恢复真实来源 IP，需要端到端协调 Nginx/Caddy，不能只信任客户端自行发送的转发头，也不能破坏既有站点协议。

## 备份

```sh
npm run backup
# Docker 中：
docker compose exec -T app npm run backup
```

脚本使用 SQLite 在线备份，包含已提交 WAL 页，并对备份执行完整性校验。直接复制运行中的 `.sqlite` 主文件可能遗漏 WAL 数据，不可作为可靠备份。数据库迁移也会在写入前自动备份已有库；全部待应用迁移在同一事务内执行，失败同时回滚结构、数据和迁移账本。

建议每日备份且在每次部署前备份，将备份加密复制到服务器外，保留最近 7 天及每月版本。备份包含私人心得和账户哈希，应与正式库采用相同访问限制。

## 恢复演练与回滚

1. 记录当前镜像版本与数据库备份路径，停止 `app`，确保没有其他进程持有数据库。
2. 将当前数据库连同 `-wal`、`-shm` 文件移动到单独保全目录，不覆盖或删除它们。
3. 将选定备份复制为 `FANJIN_DB_PATH`，恢复数据库文件所有者及 0600 权限；确认同名旧 WAL/SHM 不存在。
4. 使用与该备份兼容的镜像启动。检查 `/api/health`、首页、管理员登录、经典阅读及个人摘录。记录恢复用时和抽样结果。
5. 新版本写入过数据时，不只回滚镜像；先判断迁移是否向后兼容，必要时将部署前备份与上一镜像配对恢复。

上线前应做一次临时目录/独立卷恢复演练。测试证明迁移备份机制正确，不等于已经完成目标服务器的灾备演练。

## 内容发布

经典须填写底本、来源名称和链接、许可说明和链接，并由管理员核验。古注须有作品与卷章出处；无法核对的古注留空。不要将示例导读、自动转换或未校对资料当作权威古注。`sourceVerified` 是管理员的核验记录，不是系统自动作出的版权结论。上线内容、现代整理和音频各自需要可追溯的来源与许可。
