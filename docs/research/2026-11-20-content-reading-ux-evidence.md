# 梵烬内容与阅读体验：一手证据及实施准则

研究日期：2026-11-20。范围：内容层级、中文正文排版、阅读辅助收纳与可访问性。当前产品保持 GitHub Pages 纯静态及 IndexedDB 本机保存。本报告没有改动应用代码，也没有访问用户私人记录。

## 结论

当前需要优先解决的是「什么先看、什么后看、什么时候才出现操作」以及中文阅读版心，而不是给现有文本堆叠增加装饰。首页帮助选书和接续；书籍介绍帮助判断内容与版本；阅读页帮助连续阅读与就地记录。三类页面不能共用同一种信息密度。

建议先以九条准则重排信息，再做正文与辅助面板的版式验收。正文原文不因“精简文案”而删改；可以删的是重复解释、重复状态、无任务价值的导语，或者把次要操作移到可发现的二级入口。

## 九条可落地准则

下表的“验收目标”是梵烬的设计假设或明确的标准测试，已经区分；设计假设需要实测，不能说成这些来源已经证明了具体数值。

| 准则 | 对梵烬的改变 | 应避免 | 验收目标与证据 |
| --- | --- | --- | --- |
| **1. 每个页面先服务一个主要任务** | 首页：继续阅读/选一本书；介绍页：判断版本并开始；阅读页：读正文，按需记一条。把完整许可、所有偏好、备份解释放到相应上下文，保留清楚入口。 | 在首页同时放品牌长文、操作说明、所有偏好表单、全部记录统计；把“想展示功能”当需求。 | 设计目标：新访客无需填表就能开书；回访者无需找历史列表就能继续。每个首屏主块都能写出“读者要做X，为了Y”。依据 S8、S2。 |
| **2. 层级靠结构，不靠满屏大字** | 书名、篇章、小标题、正文、来源元数据各有稳定角色；书架卡片/行只保留识别与决策所需的书名、位置、节选标识和主动作。 | 每块都用大标题、说明段和一排标签；为了“高级感”使用含义模糊的标题或多种字号。 | 设计目标：只扫标题和书名能解释页面结构；同级内容同款式，标题更贴近自己统领的内容；不把标题画成广告。依据 S3。 |
| **3. 按语义分组，不把每一段都做卡片** | 目录分章节；原文保持自然段；同一章节连续阅读；注释与选中段落保持明确关联。用空白和对齐先表达关系，必要时才加边线/底色。 | 正文每段一个背景框、每段重复“原文/古注/导读”空标题；为“短段”强行删改古籍原文。 | 设计目标：长章与短经分别抽样，读者能指出段落/章节边界，不把一个段落误认为另一书；不存在空注释块占位。依据 S1、S3。 |
| **4. 中文行长按汉字字身测量** | 桌面先试 **28–36 个全角汉字/行**；360–430 CSS px 手机先试 **16–22 字/行**。320 px 或用户放大时接受更少字，优先重排。字号变动时版心随之调整，不只锁死 680px。 | 将 NN/g 英文 50–75 characters 直接当作 50–75 个中文汉字；以 65ch 就认定合适；从印刷 pt 数值直接得出网页 px。 | 上述是待验证起点。实测每个字号下 20 个正常正文行的字数，桌面默认尽量不超过 40 CJK 字形；保留用户收窄/放大能力。S7 的 17–40 是中文参考，S4 的 40 是 AAA 机制要求，二者不能混成硬性默认规范。 |
| **5. 行高与段落留白是一套节奏** | 先试正文 18–20px、单位化行高 1.75–1.95，段间约一行的可辨留白；章节标题与首段贴近，章节之间明显大于段落之间。短手机行可较紧，长行可稍松。 | 把“行距 50%–100%”误设成 CSS line-height .5–1；认为空白越大越舒适；注释小得必须反复放大。 | 参数为候选值。S7 明确行高=字号+行距，不能混术语。看长章连续读 5 分钟时是否串行/找回困难；统一同级段落节奏。S6 覆盖测试另做，不把 1.5 当唯一默认。 |
| **6. 保持中文排版规则与可调性** | 使用适合中文的字体回退；设置正确语言信息；测试句号、后引号不落行首，前引号/前括号不落行尾。正文先用稳定自然字距；整段注释、英文来源链接与 XML 单独处理换行。 | 全正文大字距、负字距挤字；为视觉强制插空格/换行污染原文；只换“繁简”就假定地域标点规则完全相同。 | S7 基本禁则抽样至少含 `。 ， ： ； ！ ？ 「 」 （ ）`。S7 描述传统中文齐行；S4 关注可取消强制两端对齐，梵烬应优先可读与可覆盖，不用强制 justify 拉大字距。 |
| **7. 低频工具收起，高频任务可见** | 目录、当前位置、笔记入口保留；字号/行距/主题聚合进“阅读设置”；完整底本/许可/XML 放“版本与来源”。原文默认可读，笔记只在需要时打开；读与写相互参照时就地呈现。 | 把整篇正文折叠；把“继续读/保存”藏到三级菜单；用一个“更多”装所有不同语义；多层折叠套娃；操作一段就跳走整页。 | 设计目标：日常阅读无须打开设置；常用动作至多一次展开；打开笔记仍知道引用哪段，关闭后回到原位置。最多两层披露是 S2 经验指导，频次与可发现性仍要验证；S9/S10约束哪些内容不能藏。 |
| **8. 宽屏不是必须三栏常驻** | 正文是默认焦点；桌面目录可以收起，笔记仅主动打开；窄屏变目录/笔记抽屉或单列，工具栏不挤占读区。 | 缩小窗口时维持目录+正文+笔记三列；上下固定栏把正文夹成一条；以桌面截图看起来齐整代替放大测试。 | **规范测试**：等效320 CSS px宽、200%文字放大、典型1280宽400%浏览器缩放；正文不需左右来回滚动，重要操作不丢失，聚焦控件不被遮住。依据 S5；普通阅读正文不属于二维布局例外。 |
| **9. 允许读者覆盖，不用“完美排版”封死设置** | 保留主题/字号偏好；允许浏览器缩放及用户样式。控件、标题、笔记预览容器随内容增长。截断只用于预览且能打开全文。 | 固定高度+overflow:hidden裁字；禁用缩放；对所有文字用!important压住用户样式；把三套预设主题等同完整AAA颜色选择机制。 | **规范测试**：覆盖 line-height 1.5、段后距2em、letter-spacing .12em、word-spacing .16em，内容和操作不能裁切重叠；中文不靠词间空格分词，不人为插词空格。依据 S6及其文字系统例外。 |

## 对现有梵烬结构的具体落点

研究期间只读核对了 `HomePage.tsx`、`BookPage.tsx`、`ReaderPage.tsx` 和现有 `DESIGN.md`。其他代理正在修改界面，下面是优先级与验收方向，不应当作最终页面截图审计。

1. **P0：阅读页默认聚焦正文。** 固定一条低噪声工具栏，正文留足宽度，目录与笔记状态由用户控制。设置中仅有 1.85/1.9/1.95 三个很相近行高，不一定产生有意义差别；应测试“紧凑/舒适/宽松”的实际差异，而不是靠参数数量体现功能。
2. **P0：书籍介绍页缩短“到正文的距离”。** 保留书名、节选/全本、简短底本状态与开始阅读；完整版本/许可说明按需展开，但出处和许可入口始终可见，保留法定/许可要求的完整内容。目录可以直接到正文，不让用户先读一屏以上的重复元数据。
3. **P0：首页的书架与经藏各司其职。** 回访优先一个明确的“继续阅读”；真实书架按可识别书目组织；初访直接看真实书，不先回答偏好问卷。辅助说明宜一行且就近，不每块重复“数据保存在本机”。完整备份风险说明留在备份操作处。
4. **P1：按实际任务优化注释与笔记。** 原文、古注、现代导读必须保持来源区分，但不必每段把三层都展开。没有古注/导读就不渲染空卡；笔记打开时保持段落锚点和光标，不跳到章首。
5. **P1：先整理语义与排版，再添加书封/装饰。** 封面可协助识别书目，但不能替代书名与位置，也不能成为页面最多的面积。正文页不因首页的视觉语言而每段加装饰框。

## 中文行长的验收方法

不要只记录一个 CSS `max-width`。至少保留以下测试组合与截图：

- 360、390、430、768、1280、1440 CSS px 宽；读区可用宽度与实际字号一起记录。
- 18、20、23px 三个正文档位，纸色和夜间各抽样；选择《论语》短段、《大学》长段、《心经》全角标点密集段。
- 正文每行“全角汉字等效宽度”可用 **正文内容宽度 ÷ 实际字号**作近似检查，但最终对正常行做实际字符/字形计数；英数、标点压缩、回退字体会使近似不准确。
- `ch` 反映字体中数字零的度量，不等于一个汉字；可以使用相对字身宽度设计，再以真实排版结果验证。不能写“max-width:65ch，所以中文阅读已合格”。
- 调整字号后，章内当前段落仍在视野附近；打开/关闭目录或笔记不丢当前位置。宽度改变可能重新换行，这是正常的，丢锚点则不是。

建议目标：桌面正文舒适行长 28–36 个全角字，手机360–430宽默认约16–22个；这些不是证据里的固定最佳值。最终通过使用者阅读任务验证，必要时允许用户选更宽或更窄。不要通过缩小字号来守住目标字数。

## 最小验收任务与指标

以下是拟议验收，不是已得到的用户实验结果。可先用 5 名目标读者做方向性测试，不能据此宣称统计显著。

| 任务 | 观察内容 | 建议首轮通过线 |
| --- | --- | --- |
| 初访打开《心经》原文 | 是否要读说明或填表；是否误入设置 | 5人中至少4人无需提示，20秒内进入正文 |
| 回访接着上次一段 | 继续入口与书/章定位是否明确 | 至少4人一次主要动作完成，位置正确 |
| 连续读长段5分钟 | 串行、频繁横向扫视、找回行首、旁栏干扰 | 记录主动停顿和主观舒适度，与改版前同文对照；不以“更好看”单独判定 |
| 看一条古注，再回到原文 | 区分文本来源、上下文是否保留 | 全员能说出当前是原文/古注/个人笔记；无丢位置 |
| 为一句写心得并继续读 | 引用范围、保存状态、关闭后的定位 | 至少4人无提示完成；原文快照不改写、输入不丢 |
| 320px宽/400%缩放/文字间距覆盖 | 读区、抽屉、固定栏、焦点、按钮 | 无非例外双向滚动，无裁字/覆盖关键控件；均可用键盘操作 |

不要用“减少字数百分比”“卡片更少”“首屏更空”代替任务结果。内容少但找不到正文，仍是失败。不会引入用户行为上传分析；可现场观察、匿名记录结果，或仅在开发环境人工测量。
