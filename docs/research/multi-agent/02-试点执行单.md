# 两渠道多智能体试点执行单

日期：2026-11-21。状态：**待实施；没有安装、真实模型请求或新增试点 worktree。** 本文件是桌面研究包唯一实施参考，取代旧稿中的清理命令和冲突的首选顺序。依据见 [完整报告](01-完整调研报告.md)。沿用会话已有授权，本文不另造重复审批。

## 1. 默认组合与替代分支

默认 **T3 + Codex + Claude Code + worktree + 现有门禁**，负责人在 T3 内运行。OpenCode 后加，首次只固定一个兼容大版本。

只有明确保留当前主入口时改用 HMB：Host + 已发现的 Codex/Claude 当前渠道和 DSH 声明路由。不要把 HMB 的 provider 字段当作任意 endpoint/home 切换功能。

AO、Worktree Kanban、Herdr 作为不同主流程的替代入口，不叠加管理同一批执行。不要先自写持久调度器。

## 3. 阶段 1：各渠道一次最小原生往返

任务例：“只读取本项目 package.json 的 name，返回值和文件依据，不修改文件、不联网检索。”每次有唯一 run/task/attempt、固定 cwd 和输入摘要。

分别记录 requested（请求目标）、native_readback（运行时生效选择）、provider_reported（服务端声明）和 unknown。读回不证明中转的物理上游；未提供用量的字段记 unknown，不记零。

Codex JSON 输出逐行解析事件；stdout/stderr 分开。进程退出、原生最终状态、答案格式、产物内容和检查分别判断。不要把 CLI 的错误答案或截断事件算通过。

恢复绑定原 session、配置作用域、渠道和 cwd，不用“最近会话”猜测。原生请求结束后确认本次执行资源停止。

**通过条件：**两条渠道都有真实原生往返和正确产物，未串线。仅该阶段通过，不能宣布并发与恢复通过。

## 4. 阶段 2：自动派发与回传

负责人分别派两个独立只读问题：A 查大经加载/检索模块，B 查阅读位置/书签/简繁兼容；要求返回代码位置与可验收建议。由负责人发送一次有界补充说明、等待和读取结果，不由用户手抄。

T3 内部用 delegate 和任务状态入口；外部助手用 thread launch/read/wait，不能借用内部 caller-only 身份。HMB 只从实际可用目录选 Worker，锁定任务和会话身份。

审阅权限按运行时验证；单独禁止 edit 不代表 shell/MCP 无法写文件。此试点不以严格 OS 沙箱为目标，但必须区分真正已验证的工具限制与提示词约束。

**通过条件：**无人工搬运、无错会话回传，状态与结果有证据；取消请求及其终态能区分。

## 5. 阶段 3：双工作树实现

任务需选真正可分的两项低风险修改；“大经按章加载”只是建议题，先冻结公共契约。共享类型、锁文件、集成与发布归负责人。

**每个 run 选择唯一生命周期所有者：**

- T3 路线：T3 创建、记录和回收任务 worktree；负责人读取返回身份验收，不另建同任务副本。写任务显式 `isolation: worktree`。父未提交输入需先选定、固化后再派发。
- HMB 路线：采用其 managed checkout，由 Host 验收；不另让外部工具回收同一副本。
- 原生/Herdr 路线：负责人预建并记录 worktree，由同一负责人回收。

如所选工具不能满足本次副本要求，先换用明确的外部副本策略并停用其重复管理；不能让两个所有者同时创建/删除同一资源。

每个工作者返回固定 commit/tree 或二进制安全 patch、改动清单、已运行检查与未完成项。负责人同时查提交后、暂存、未暂存和未跟踪成果，拒绝范围外修改。

在专用集成副本整合，冲突处理后运行 **`npm run check:release`**。构建与隔离浏览器验收对应同一集成代码/同一构建；不能只跑旧 dist 上的 E2E。记录环境、基线、集成提交、产物与完整结果。

**通过条件：**固定成果与范围正确；独立审阅和完整门禁通过。源码完成、测试通过、合并和发布分别记录，不因任务状态自动发布。

## 6. 阶段 4：取消、重启、重复派发与限流

仅在专用演练副本故障注入。验证：根进程先退出、取消期间派生子进程、回执丢失、负责人重启、同一请求重试、用户原有进程同时存在。

优先复用所选宿主的原生生命周期；记录可核归属、创建时间、session 和执行 handle/Job 证据，不按进程名称批量杀，不依赖裸 PID 作为长期身份。

至少区分 queued、running、cancel_requested、stopping、delivered、accepted、failed、shutdown_unknown。发出 cancel 不等于已停；shutdown_unknown 保留工作树、日志和槽位，不自动重派。

同一动作重试复用对应幂等身份；但不能凭一个 task_id 或 state.json 宣称已处理所有崩溃窗口。恢复先核真实运行和已交付产物。

区分原生重试与编排重试、网络重试与代码返工。默认建议并发工作者2、各渠道先1、一层委派、自动代码返工最多1轮；这些是试点建议值，须核宿主能实现，不能伪装为产品默认。HTTP mock 只算辅助逻辑证据。

**通过条件：**无重复执行、误杀和配置串线，停止证据明确；未知保留为未知。

## 7. 按归属清理与回退

只处理本次创建清单中的资源：规范化绝对路径，核工作树/session/端口/浏览器 context 身份以及 reparse point 边界。保留可恢复成果后按安全移除语义逐项回收；失败就保留并报告。

不递归删除共享 wt/homes 父目录，不删除原有 worktree，不清空认证目录，不关闭用户浏览器，不停用户已有服务。只关本次自建且任务已结束的标签/context/服务。配置目录默认保留，另外的清理授权不能由本报告自动生成。

试点不达标时回到原单代理流程，保留失败证据与成果；不要同时再套另一编排器。
