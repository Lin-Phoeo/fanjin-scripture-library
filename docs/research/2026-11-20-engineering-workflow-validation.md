# 工程流程落地与浏览器收尾

## 本轮范围

按已建立的 [智能体规范](../../AGENTS.md)，核对接手、开发、内容扩刊、验证、发布和交接的实际链路，并补齐自动化。用户随后指出：测试和调研打开很多 Chrome 标签，结束后没有关闭。本轮将资源清理纳入相同流程，保留现有产品设计与经典内容。

来源目录的 Git blob 元数据可能与已保留的底本版本不同。检查以 coverage 和源文件 SHA256 确认实际底本，以 inventory 确认身份和审核状态，不把目录快照误当下载文件的版本。扩展新的来源体系时，应增加明确证据路径与检查，不将未知来源自动放行。

## 当前开发路径

任务范围 → 按需取证 → 明确文件所有权并行实现 → 定向验证 → `check:release` → 审计与差异审阅 → 已授权发布 → 对应提交线上核验 → 自有资源清理 → 状态与知识沉淀。

只改文档时，本地使用 `check:docs`；修改应用、内容、构建时用 `check:pages`；发布使用 `check:release`，在同一最新构建上追加浏览器检查。`test:e2e` 单独执行只测试现有 `dist/`，不能代替构建。完整流程和阶段结束条件见 [WORKFLOW.md](../agents/WORKFLOW.md)。

PR与Pages均执行完整门禁，失败不部署；失败trace/截图保留7天。测试数据来自隔离context，不使用真实用户记录。CI结果需逐提交核验，不把本报告当作实时绿灯。

## 实际验证

- `npm run check:release` 通过：17份现行文档检查、lint、应用/工具/旧服务端类型、Pages构建、静态目录、本机状态/API、内容来源、语言规则、3项Python解析测试、3组真实浏览器回归。
- 当前全部67个版本、37,085段按manifest核验；16种损坏/缺证据/待核许可等负向情形均按预期拒绝。这是本轮快照，不是长期固定数量。
- 独立审阅发现文档检查器把盘符当URL、误扫代码围栏的两项问题，已修复，并通过对应负向/示例回归和定向lint。
- 依赖审计0漏洞；新依赖只有测试用 `@playwright/test` 及其锁定依赖，未引入到网页运行代码。
- 正常浏览器回归结束后4178预览端口没有监听。另在忽略目录运行故意抛错的临时用例，得到预期exit1；事件证据为 `pageClosed/contextClosed/browserDisconnected` 全true，随后端口同样释放。该失败是清理探针，正式3组用例全部通过。
- 对照精确标签ID关闭9个本项目遗留测试/调研页；保留用户当前阅读页及无法确认归属的页面。关闭API响应后短暂仍能列到标签，第二次查询才确认消失，因此收尾不能只判断关闭请求成功。

本地收尾证据：`output/engineering/browser-cleanup.json`、`output/engineering/e2e-failure-probe/lifecycle.json`。正式浏览器截图/trace位于 `test-results/e2e/`；这些目录被忽略，不随站点或Git提交。此处不包含全部跨浏览器/辅助技术覆盖，也未验证进程被系统强杀时能即时清理；被强杀后的接续工作需要检查遗留归属。

## 沉淀与维护

项目事实留在权威文档与本报告；可复用的决定、教训和操作步骤归档至用户知识库。后续智能体按任务读取，不整库加载；只有真实变化才更新状态。浏览器收尾规则适用于之后的开发测试和网页调研，仍须保留用户页面与明确交付的预览。
